# Calendar 동기화

## 신청 상태 특강 누락 시 Calendar 생성

목적: 신청 상태 특강의 Calendar 일정이 없을 때 동기화로 일정이 추가되는지 확인한다.

준비:

- 신청 상태 특강을 준비한다.
- 케이스 1에서는 해당 특강의 Calendar 일정과 특강-캘린더 연결 정보를 모두 제거한다.
- 케이스 2에서는 특강-캘린더 연결 정보는 남아 있지만 실제 Calendar 일정만 없는 경우를 만든다.

실행:

1. 접수내역 동기화를 실행한다.
2. background service worker 응답과 console output을 확인한다.
3. Google Calendar UI 또는 API로 생성된 일정을 확인한다.

기대 결과:

- Calendar에 `somaManaged: "1"` 일정이 생성된다.
- 특강-캘린더 연결 정보가 생성된 Calendar 이벤트를 가리킨다.
- 케이스 2에서도 Calendar 일정이 재생성되고 연결 정보가 갱신된다.

## 취소 상태 특강 잔존 시 Calendar 삭제

목적: 취소 상태 특강의 Calendar 일정이 남아 있을 때 동기화로 삭제되는지 확인한다.

준비:

- 취소 상태 특강을 준비한다.
- 해당 특강의 Calendar 일정은 남겨둔다.

실행:

1. 접수내역 동기화를 실행한다.
2. background service worker 응답의 삭제 통계를 확인한다.
3. Google Calendar UI 또는 API로 해당 일정 삭제 여부를 확인한다.

기대 결과:

- Calendar 일정이 삭제된다.
- 특강-캘린더 연결 정보에서 해당 특강이 제거된다.

## 동일 특강의 신청 이력과 취소 이력이 공존할 때 최종 신청 상태 판단

목적: 같은 특강이 신청 상태와 취소 상태 양쪽에서 발견될 때 최종 신청 상태를 우선하는지 확인한다.

준비:

- 같은 특강이 신청 상태와 취소 상태 양쪽에 잡히는 fixture를 준비한다.
- Calendar 일정이 있는 케이스와 없는 케이스를 모두 준비할 수 있다.

실행:

1. 접수내역 동기화를 실행한다.
2. 상태 판정 결과와 Calendar 결과를 확인한다.

기대 결과:

- 별도의 `재신청` 상태는 생성되지 않는다.
- 해당 특강은 최종 신청 상태로 판단된다.
- Calendar 일정이 이미 있으면 삭제되지 않는다.
- Calendar 일정이 없으면 동기화 중 생성된다.
